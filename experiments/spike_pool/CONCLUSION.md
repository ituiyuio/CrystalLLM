## 一、初心

让**单个参数承载更多的智能**，向信息论极限靠拢。

具体化为一次可检验的尝试：INT8 参数池（4.29B 参数 @ ~4GB，消费级显卡可容纳）
+ 内容寻址稀疏激活（top-K 路由）+ 原生低精度训练（FP32 累加器 + 随机提交），
验证"智能/参数"能否超过稠密 transformer。

## 三、关键测量结果

### 标定（803k token 语料，in-sample）

```
uniform   8.32 nats / PPL 4096
unigram   7.04 / 1137      ← 「只背词频」
bigram    3.54 /   35
原版 SpikeLLM (1k 步) ~8.29 / ~3970   ← 比 unigram 还差 1.2 nats：被锁死
```

### 证伪阶梯（300 步，d=4096 / blocks=64 / K=16 / B=256）

```
E1 纯外壳（无池子，直注输入，全 CE）        PPL 32   ← 外壳/优化无罪
E2 池子 + CE 残差（无输入项）               1920    ← 代理目标税
E3 池子 + 逐通道 γ                          2714    ← 递归容量非瓶颈
E4 池子 sum 注入（W@S 淹死输入，130x）      1797    ← 归一化共用不行
E5 旁挂: γS + g·norm(embed) + g_w·norm(W@S)   38   ← 池子不再有毒…
E6 E5 + BPTT（B=128/150 步）                236*    ← …但 g_w 0.05→0.013
                                                     （池子被优化器静音）
```

### 吞吐

```
chunk 化: 19.1x (GPU 池) / 15.5x (CPU pinned 池) / 端到端 8.5x
C=1 bitwise 对拍一致；CPU 池仅慢 23% —— 池容量与显存解耦
训练绝对速度: ~5.6k tok/s @ 268M 活跃参数 ≈ 稠密 transformer 的 1/10
```

## 四、为什么初心没有兑现（信息论尸检）

初心「单参数压缩更多智能」在信息论上是真命题，但本次实验给出了它的
完整代价结构。**智能/参数 ≈ 参数信息量 × 功能通道 × 梯度充分性**：

1. **参数信息量**（我们唯一优化的项）：INT8 相对 BF16 密度翻倍，真实但有限
   ——且业界已证明 4-bit 甚至 1.58-bit 几乎无损，纯表示密度的红利更薄。
2. **功能通道**（本次实验的致命发现）：**状态容量决定参数的价值上限，
   参数总量不决定智能**。4.29B 参数挂在 4096 维向量态 + 标量 γ（~20 token
   滑动平均）上，无论多少参数，可验证贡献 ≈ 0（g_w → 0 是优化器自己投票的）。
3. **梯度充分性**：MSE-to-embedding 代理目标给参数的学习信号有天花板
   （E2: 1920），只有端到端 CE 才让参数拿到诚实的梯度。

### 三个可迁移的结构性检查表（本次最有价值的产出）

任何新架构候选，在投入工程之前先过这三问：

- [ ] **和崩塌检验**：稀疏求和的分支有没有逐分支非线性？
      无则 Σ 求和 ≡ 一层线性，稀疏是装饰。（本项目的教训：块=纯线性矩阵）
- [ ] **状态容量检验**：智能上限由状态（向量/矩阵/KV）的结构决定。
      问：参数翻倍时，状态容量跟着涨吗？不涨则参数在堆死重。
- [ ] **目标通路检验**：每个参数是否都在端到端目标的活跃梯度路径上？
      任何手工梯度/代理损失都要给出与端到端梯度等价性的论证。

### 对「信息论极限」的最终认识

每比特智能的极限， field 里已被验证的现实杠杆是：**量化**（BitNet 1.58-bit）、
**蒸馏**、**过训练**（Chinchilla 逻辑：小模型喂穿数据）——三者全都保留
transformer、在别处挤压。想靠"发明新架构让参数更聪明"入场，要背负三者中
最重的举证责任，而其核心难点恰好是上面三个检查表。本项目的初心方向没错，
杠杆选在了举证责任最重的位置上。

## 五、资产清单（封存不等于销毁，带走这些）

1. **系统资产**（架构无关，可直接搬运）：
   - chunk 引擎：一次 dequant 服务 C 位置 + 掩码 GEMM 批量更新 → 19x
   - INT8 原生训练规则：FP32 累加器 + 随机提交（无偏、节奏自适应）
   - CPU pinned 池 + 事件协议预取：23% 代价换无限池容量
2. **方法资产**：标定(uniform/unigram/bigram) → 单因素消融 → 判据前置的
   证伪流程。本次 E0-E6 总耗时约一个下午，19x 引擎是它的前提。
3. **认知资产**：第四节的三个检查表。
4. **工程发现**（基线遗留，若重开先修）：
   - `train_engine.py` 所有 commit 路径的 int8 回绕溢出
     （`clamp(W+step)` 先回绕后 clamp；修法：int16 加法再 clamp）
   - `forward_step_state` 每位置 `empty_cache()` 纯损耗（实测 0 收益）

## 六、复活条件

仅以下情形值得重开本线（或其衍生）：

1. 块结构升级为真 mini-FFN（`W2·σ(W1·S)`）后，在 ≥2k 步长跑中 g_w
   稳定上升且 E5 型模型 held-out PPL 超过无池子外壳——池子证明增值；
2. 矩阵态记忆槽（每块一个 INT8 kv 槽 + surprise 门控写入）作为独立
   长上下文记忆模块，在 needle-in-haystack 协议上超过同内存占用的
   Mamba/小 transformer 基线；
3. 出现以「参数驻 CPU RAM + O(1) 状态 + 流式无限上下文」为硬需求的
   端侧产品场景（本架构的三项真实资产恰好全部服务于此）。
